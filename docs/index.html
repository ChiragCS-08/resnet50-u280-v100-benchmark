The project in brief

Two accelerators in the Open Cloud Testbed run the same network, ResNet-50 (6.97 GOP per image, ImageNet, 224×224×3 input).

  • FPGA: AMD Alveo U280 running AMD’s DPUCAHX8H deep-learning processor in INT8, programmed through the Vitis AI flow (Model Zoo, Quantizer, Compiler) and the VART host runtime.
  • GPU: NVIDIA Tesla V100-PCIE-32GB running PyTorch in FP32. This is the accuracy and performance reference, with INT8 TensorRT as an optional extra.

This is a measurement project, not a from-scratch RTL design. The DPU IP comes from AMD. The engineering work is getting it built and running on the OCT shell, checking correctness against an FP32 golden reference, and benchmarking fairly.

Full-project targets: Top-1/Top-5 on 5,000 ImageNet validation images with the INT8 path within 2% absolute of FP32; batch sizes 1 to 32; end-to-end and kernel-only latency; throughput; power from xbutil and nvidia-smi.

  • Weights: torchvision ResNet50_Weights.IMAGENET1K_V1, batch 1, seed 0, PyTorch 2.14.1 with CUDA 12.6.
  • The published full-validation figure for these weights is about 76.1% Top-1 and 92.9% Top-5. The 5,000-image subset is within normal sampling noise of that, and the 100-image numbers are too small to mean much.
  • The run took 141.6 seconds including image decoding and preprocessing. That is not a throughput benchmark, which comes in Layer 3.
  • Reproducibility: two runs on the same image list produced byte-identical prediction files.
  • Known limitation: the FPGA path uses the Vitis AI Model Zoo TensorFlow ResNet-50, which has different weights from the torchvision model. The accuracy comparison is therefore cross-framework.

How to run

GPU reference (V100 node)

  1. Create the environment. The cu126 wheel is required; the default PyTorch wheel has no V100 kernels. 
    python3 -m venv ~/venv-gpu && source ~/venv-gpu/bin/activate
pip install --upgrade pip
pip install torch==2.14.1 torchvision --index-url https://download.pytorch.org/whl/cu126
  2. Make a synsets file (1,000 sorted class ids) and a labels file (filename,wnid): 
    LC_ALL=C ls /proj/octfpga-PG0/imagenet/val | sort > synsets.txt
find /proj/octfpga-PG0/imagenet/val \( -type f -o -type l \) -printf '%f,%h\n' | sed 's#,.*/#,#' > labels.csv
  3. Reproduce the golden output and check it: 
    python gpu_ref/fp32_reference.py --images /proj/octfpga-PG0/validation \
    --labels labels.csv --synsets synsets.txt --list data/image_list.txt --out results_100
diff results_100/fp32_predictions.csv data/fp32_predictions.csv && echo IDENTICAL

Expected: IDENTICAL, with Top-1 81% and Top-5 95% for the 100-image list. Use --num 5000 instead of --list for the full baseline. The diff against the committed golden file is the test.

Risks and blockers

No DPU binary for the OCT shell

AMD’s package targets the older shell xilinx_u280_xdma_201920_3. The OCT card uses xilinx_u280_gen3x16_xdma_1_202211_1, so the design must be rebuilt, and it may fail timing.

No Docker or VART on the run node

The runtime has to be built or provided, and the quantizer and compiler environment is still unresolved.

Cross-framework weights

See the limitation under Results. Both paths will use the same 5,000 images.

Power measurement differs by tool

xbutil and nvidia-smi report differently. The sampling method will be documented and repeated runs averaged.
